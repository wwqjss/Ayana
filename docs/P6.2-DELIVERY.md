## 范围与架构基线

以当前仓库、Git 历史和部署实机为准：P4.4 已退役旧 Council，P6/P6.1 已建立新的自治链。本轮接手 P6.2，不继续拆除 P6.1，也不回退到 P4 的只读产品阶段。

- 旧 Council / AgentLoop / `_bg_agent` / `_bg_autonomy` 及旧 `auto`、`reviewed` 执行授权继续停用；历史数据保留。
- 当前链：告警 → Incident / Session → AutoInvestigator 只读调查 → MiMo 决策 JSON → OpsLoop → ActionService `autonomous` → 验证 / 结案或人工升级。
- 调查与决策会话均不能自行写主机或调用写工具；实际执行由 Python OpsLoop 统一派发，避免模型决策时执行一次、OpsLoop 再执行一次。
- 人工 `manual` 的 Policy / 审批不变；SSH 凭据、host key、对象绑定、锁、幂等、`unknown` 禁重放和验证契约保留。

生产原有 `auto_investigate.enabled=true`、`closed_loop=true`，本轮不改这些开关。新增的凭据验证门禁在未验证时保留排队任务、不占用调查轮次、不调用模型；新密钥验证后，现有新自治 Worker 可处理新任务。

## 审查发现与修复

### 配置、验证与密钥

1. 按实际服务账户读取 MiMoCode XDG 配置；CLI 路径支持顶层配置回落至 `auto_investigate.mimo_bin`，模型以 Web 当前保存配置为准。
2. JSONC 支持注释、尾逗号和字符串转义，畸形或重复键配置拒绝覆盖；保留已有 MCP、permission、其他 provider/model 选项。
3. 配置写入使用私有临时文件、fsync 与原子替换，失败保留原文件；密钥只存本机私有配置，不入参数、数据库、审计、UI 回填或 Git。
4. 空密钥表示复用当前选中 provider 的已保存密钥；改变 provider/服务地址而未提供新密钥时拒绝转发旧密钥。
5. “保存并验证”使用有总超时、32 token 上限、不跟随重定向的真实 `/chat/completions` 请求；限制公开 HTTPS 和解析后的公开地址。HTTP 200 必须含有效非空模型回复，代理 HTML/空 choices 不算通过。
6. 网络响应完整读取至 EOF，累计超过 64 KiB 拒绝；覆盖分段/chunked JSON，防止单次短读误判。
7. 验证指纹绑定配置路径、provider、model、URL、密钥。运行时用同一份凭据快照比对并构造子进程配置；清除或外部修改后立即失效。
8. 草稿测试不认证其他已保存配置；已保存配置复测失败会撤销认证。数据库状态写失败明确报错，不能假报可用。
9. API 只输出固定错误分类；管理日志、CLI 输出及异常进行密钥脱敏。保留 admin、CSRF、Origin 和 Incident 可见性检查。

### Web 与运行链

- 保存、测试、聊天等外部等待移出 Web 主循环；后台调查 attach/resume、决策 create/resume 同样在线程中执行，模型等待时 Web 仍可响应。
- UI 使用当前选中 provider 和完整模型 ID；密钥始终留空，防止重复点击、过期响应污染状态，清除后刷新实际可用性。
- MiMoCode 子进程使用明确 binary / model / cwd / 配置路径和内容；每次调用重新解析验证后的配置，换密钥或模型不依赖 Worker 重启。
- 子 MCP 绑定当前 Python、`ayana.mcp_server`、真实配置目录和 `AYANA_MCP_DB_PATH`，防止工作目录变化连接到另一个空库。
- 决策正确读取生产 `RemoteSession` 对象，不再只支持测试字典；CLI 非零退出或 error event 不能凭 sessionID/旧文本算成功。
- `suggested_action` 仍要求明确 `evidence_ok=true`；旧代、已关闭 Incident 或已失效 provider 的结果不能继续执行。
- MCP `action.execute` 要求 Incident 并经过 OpsLoop 硬轮次限制；调查与决策两种 profile 均有工具 allowlist / permission 和服务端只读限制。
- 修正 P6.1 隔离测试 FakeGate 缺少 `host_id_verified_at` 的夹具问题，并强化真实 Action 状态和单次模拟派发断言；未放宽生产 host 校验。
- 后台调用真正并发后，原 P4.3 测试的共享 FIFO 假回复按线程时序分配 A/B，出现一次全量失败；改为按 Incident 绑定假回复、Barrier 验证真实并发并强化独立 Session 断言，未删测或放宽断言。

取消后台等待不会强杀已运行线程；CLI 自身仍有超时。晚结果可能更新会话元数据，但不作为成功调查继续进入自治执行。未在本轮重新设计并发预算或跨代压力控制。
