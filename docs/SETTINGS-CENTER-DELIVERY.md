## 范围

按用户确认的布局，将分散的账号和系统配置收进一个独立设置窗口。用户明确指定浏览器交互由其验收，本次交付采用自动回归与服务端部署核验，不代替用户操作浏览器验收。

- 点击用户名展开账号菜单：个人资料、双重验证、设置、退出登录。
- 居中双栏设置窗口：模型、个人资料、双重验证、提示词、技能、系统连接、关于。
- 左侧分类，右侧独立滚动，底部操作区；桌面/窄屏样式和键盘焦点支持。
- 设置窗口独立于通用业务弹窗；修复共享弹窗遗留动态按钮以及重复标题/保存入口。
- 分类切换、关闭和退出前保护未保存内容；保存中防重复提交和离开；过期响应不能覆盖新栏目。

## 功能落地

| 栏目 | 行为 |
|---|---|
| 模型 | 主表单配置 MiMoCode 自治模型，沿用真实测试和保存验证；折叠区域保留表单辅助模型，明确用途和独立保存范围 |
| 个人资料 | 查看真实用户名/角色、修改密码；密码保留空格，普通改密后全部会话撤销并重新登录；强制改密独立流程保留 |
| 双重验证 | 认证器 TOTP 绑定/更换/关闭、扫码或手动添加、一次性恢复码；显示真实启用状态，服务端轮换会话后更新 CSRF |
| 提示词 | 调查、处置、运维软约束分别编辑，保存/恢复形成可追溯版本；下一次模型调用采用新内容 |
| 技能 | 展示服务账号和项目目录实际发现的技能、来源与路径；发现与加载分开，缺少运行时证据时明确显示加载待确认 |
| 系统连接 | Prometheus/Alertmanager 地址及状态、按会话连接的 MCP 说明、迁入现有通知渠道表单 |
| 关于 | Ayana/MiMoCode 版本、真实项目地址、只读检查正式发布版本、保留旧自治费用历史 |

通知渠道复用原节点和既有事件绑定，原 ID 唯一；通知业务页保留引导入口，消息记录、发送队列与节点状态不变。未保存的渠道输入有离开提醒；确认放弃后清掉敏感输入，包括 URL 查询参数中的凭据。添加失败保留输入，成功后清理对应草稿；没有自动发送测试消息。

## 后端修复与边界

- 修复 Prometheus `resultType=scalar` 被当作 vector 逐项解析而触发 `'float' object has no attribute 'get'` 的根因；支持正确的 scalar/string/vector 形状，拒绝无效响应，界面只输出可读连接错误。
- 提示词复用现有 `config_versions`。新旧保存/激活入口、唯一生效切换与审计处于同一 SQLite 事务；首次读取前 `BEGIN IMMEDIATE`，覆盖独立 MCP/Database 连接的并发写入。
- 管理设置 API 保留 admin、CSRF、Origin 检查；“关于”仅向已登录用户返回公开版本信息，OTP 与个人资料使用原有账号鉴权。
- 技能扫描限定服务账号/运行目录，拒绝符号链接越界，有深度/数量/文件大小限制；先递归脱敏原始字符串，再序列化，覆盖包含引号和反斜杠的合法密钥。
- 检查更新只请求固定公开 GitHub 正式版本地址，有超时和大小限制、拒绝重定向，不安装或执行更新。无正式 release 时明确报告，不能假称最新版。
- 当前 Incident → Session → AutoInvestigator → MiMo 受限调查/决策 → OpsLoop → ActionService 链保持；旧 Council 继续退役。
- 提示词不改变工具 allowlist、只读环境、Policy/人工审批、SSH host key、幂等、unknown 禁重放及执行验证保护。
- 不修改生产密钥、连接配置或自治开关；schema 仍为 21，没有新增数据库迁移或删除历史数据。
