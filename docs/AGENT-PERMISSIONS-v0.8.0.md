# Ayana v0.8.0 会话执行权限

日期：2026-10-27（Asia/Shanghai）。基线 `a07dafd`，分支 `speed-supreme`。

## 行为与界面

- Agent 设置分别保存自动值班执行权限（只读/读写）与审批模式（人工/自动）。旧 `require_human_approval` 仅兼容自动值班审批，与新字段原子同步。
- 工作台接管按钮旁显示会话权限拨动与审批选择。观察时不可操作，显示后端确认的实际权限；接管成功原样继承权限及审批模式。
- 接管覆盖绑定当前用户、终端连接和 60 秒租约。切换不获取任务执行锁，不重启 CLI，不更换 RID，也不修改自动值班配置。
- 释放、连接断开、租约过期、Web 或原生运行服务重启撤销覆盖。自动会话恢复最新全局配置；手动会话恢复自身基础状态。
- 前端使用后端权限版本，忽略旧响应，切换失败显示原因和确认状态。后端确认控制权失效时停用键盘和权限控件。
- 原生 MiMoCode 仍是唯一中央工作区；没有恢复网页聊天或增加第二个任务输入框。

## 实际授权链

1. 受管原生运行时使用中性 `ayana` Agent，稳定提供现有全部 Ayana MCP 工具的 schema。模式变化无需改变当前回合的工具列表。
2. MCP 声明 MiMo 原生 `com.xiaomi.mimo/turn-lifecycle` version 1。工具调用的原生 `_meta` 提供 RID、turnId、actorId；模型 `arguments` 无法决定授权会话。
3. `agent_authority.py` 从真实唯一 RID 映射读取一致数据库快照，合并自动全局/手动基础/有效接管覆盖。缺元数据、未知或歧义 RID、绑定冲突均拒绝。
4. `OpsContext` 按调用复制，不修改共享只读状态。显式硬只读的旧 MCP 客户端继续硬只读；未启用受管上下文的实例保留原行为。
5. 只读拒绝写；读写下的 shell、Incident/知识/配置变更进入现有写台账与审批路径。人工审批通用变更使用服务端私有派发入口，模型提供 `approved` 参数无效。
6. ActionService 保存可信会话 ID，在提案、身份核验后的领取事务和 SSH 派发前重新校验。自动批准后改成人工审批时，尚未派发的系统批准退回待审批；真实人工批准沿用。
7. SSH host key、原有端点及凭据选择继续生效；原生 Bash/本地 shell 不开放，避免绕过既有 Ayana 工具链。权限切换不隐式更换账号。只读命令仍使用原有严格参数校验。
8. 已派发的远端命令无法被权限降级撤回；降级约束后续调用及尚未派发的命令。不杀死 CLI，也不重放任务。派发前拒绝与执行结果不确定分别处理，`unknown` 仍禁止自动重放。

接管、恢复、切换前后权限、实际写结果与拒绝原因进入审计。通用待审批操作按真实 SID 关联，手动无 Incident 的会话也能展示待审批项。待执行命令与参数完整保存，去掉会改变实际执行内容的截断。

## 数据与兼容

Schema v23 → v24 只增加权限与覆盖字段、配置及版本号，不删除表或历史。

- 自动值班初始 `readwrite`，保持原 ActionService 闭环已有的写能力；审批从原总开关迁移。
- 已有手动/历史会话保留原生 MCP 的实际只读状态，审批继承迁移时原设置。
- 新手动会话具有独立 `readwrite` 基础状态，审批默认捕获迁移时设置，之后不跟随自动值班全局变化。接管后可临时调整。
- 迁移幂等，重复调用不覆盖已保存的会话权限。
- 不修改生产自动调查开关、SSH 凭据、生产配置文件或 sandbox。
